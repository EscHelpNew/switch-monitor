# Switch Monitor

Небольшой монитор Nintendo Switch для трея Windows. Самостоятельный проект: для работы не нужны исходники игры или другого приложения.

В отдельной папке [switch-debug-kit](switch-debug-kit/README.md) находится комплект для разработчика: приёмник обновлений NRO с автоматическим перезапуском, клиент ПК, нативный ARM-стенд и инструкция подключения к другой игре. Начните с [README](switch-debug-kit/README.md); для ИИ есть [AGENTS.md](switch-debug-kit/AGENTS.md). Трей остаётся пассивным: установка комплекта в игру выполняется отдельно.

Репозиторий: [EscHelpNew/switch-monitor](https://github.com/EscHelpNew/switch-monitor).

## Состав проекта

| Путь | Содержимое |
|---|---|
| `src/Monitor.cs` | Монитор служб Switch и значок в трее Windows |
| `tests/MonitorTests.cs` | Локальные тесты монитора |
| `build.ps1`, `run.cmd`, `run.ps1` | Сборка и запуск монитора |
| `config.example.json` | Пример настроек монитора |
| `switch-debug-kit/` | Приёмник, клиент ПК, ARM lab, примеры, документация и тесты |
| `package.ps1` | Архив публичных исходников обоих компонентов |
| `build/`, `data/` | Локальные результаты сборки и настройки; исключены из Git |

## Получение исходников

```powershell
git clone https://github.com/EscHelpNew/switch-monitor.git
cd switch-monitor
```

Можно также скачать ZIP исходников на GitHub и распаковать его в доступную для записи папку.

## Запуск

Дважды нажмите **`run.cmd`**. При первом запуске утилита автоматически собирается штатным компилятором Windows. Установка библиотек через интернет не требуется.

Нужны Windows 10/11, Windows PowerShell 5.1 и .NET Framework 4.8. Если значок скрыт, откройте стрелку рядом с часами Windows и перетащите его на панель.

- **Зелёный:** получен ответ ping или удалось установить TCP-соединение с одной из служб консоли.
- **Красный:** ни одна проверка не получила ответа.
- **Серый:** первая проверка или мониторинг на паузе.

Наведите мышь на значок, чтобы увидеть IP и приложение. Правой кнопкой открывается меню со службами, временем проверки, сменой IP, паузой и выходом. Двойной щелчок открывает подробности.

## Язык интерфейса

По умолчанию интерфейс на английском. В меню трея откройте **Language → Русский** или **Язык → English**. Меню, подсказка значка и открытое окно подробностей переключаются сразу, без перезапуска.

Выбор сохраняется в `data/config.json`: `"Language":"en"` или `"Language":"ru"`. Старый конфиг без этого поля и неизвестный код языка используют английский, сохраняя остальные корректные настройки. Поля `Application` и `Services` в `data/status.json` остаются на английском для обработки скриптами.

## Что определяется

| Служба | TCP-порт | Отображение |
|---|---:|---|
| Служба игры или приложения | 28281 | Игра (TCP) |
| ARM lab | 28284 | ARM lab (TCP) |
| GDB-сервер Atmosphère | 22225 | GDB; приложение не определено |

Открытый порт означает доступность TCP-службы. Он не подтверждает отсутствие зависаний, FPS, авторизацию или то, какое приложение находится на переднем плане. Если отвечает только ping или GDB, приложение честно помечается как неопределённое. Нужны уже включённые службы консоли: утилита их не устанавливает и не включает.

Проверка выполняется раз в пять секунд в фоновом потоке. Токены не читаются, команды управления, отладки и запуска не отправляются. TCP-соединения сразу закрываются без передачи данных. Порт netloader 28280 не опрашивается, чтобы не вмешиваться в загрузку NRO. Для чистого замера производительности можно включить паузу в меню.

IP по умолчанию — `192.168.1.131`. Настройки сохраняются в `data/config.json`, текущее состояние — в `data/status.json`. Можно скопировать `config.example.json` в `data/config.json` до запуска. Изменения файла настроек применяются при следующем запуске; смена IP через меню применяется сразу.

Некорректный или неполный JSON заменяется настройками по умолчанию. При смене IP во время уже идущей проверки новый результат появится не позднее следующего интервала.

Повторный запуск из той же папки не создаёт второй монитор. Утилита не добавляет себя в автозагрузку.

## Сборка и тесты

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
```

Готовый файл: `build/SwitchMonitor.exe`. Для распространения скопируйте EXE в каталог `build` рядом с исходной структурой либо запускайте с `--root "путь к папке настроек"`. При обычном запуске `run.cmd` путь определяется автоматически.

Разовая проверка с результатом в JSON:

```powershell
Start-Process .\build\SwitchMonitor.exe -ArgumentList '--probe-once', 'probe.json' -Wait
Get-Content .\probe.json
```

Тесты используют только localhost: проверяют IPv4, состояния служб, JSON, открытый/закрытый порт и отсутствие отправляемых команд. Они не обращаются к Switch.

Проверка комплекта разработчика выполняется отдельно:

```powershell
python .\switch-debug-kit\tests\check.py
```

Для неё нужны Python 3.11+, MinGW-w64 GCC и установленный devkitPro/devkitA64 с libnx и switch-tools. Для самого трей-монитора эти инструменты не нужны. Требования и порядок интеграции описаны в [Switch Debug Kit](switch-debug-kit/README.md).

## Распространение

В Git хранятся исходники, примеры и документация. Каталоги `build/`, `data/`, а также `switch-debug-kit/build/`, `switch-debug-kit/data/` и локальный `switch-debug-kit/project.json` исключены через `.gitignore`. EXE можно приложить отдельно к GitHub Release. Локальные настройки и токены не входят в публикуемые исходники.

Чистый архив исходников без локальных данных и EXE:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\package.ps1
```

Результат: `build/switch-monitor-source.zip`. Состав комплекта разработчика задаёт явный список [package-files.txt](switch-debug-kit/package-files.txt); локальные данные не добавляются в архив автоматически.

Происхождение файлов комплекта разработчика и исходные контрольные суммы сохранены в [PROVENANCE.json](switch-debug-kit/PROVENANCE.json). Клиент, приёмник и мост используют протокол версии 2 и собираются из одной версии исходников. Проверка интеграции на конкретной консоли описана в [VALIDATION.md](switch-debug-kit/docs/VALIDATION.md).

Основа трея — штатный [Windows Forms NotifyIcon](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon).
