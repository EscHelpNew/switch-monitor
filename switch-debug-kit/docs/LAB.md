# Нативные тесты на Switch

Стенд — отдельный NRO, который остаётся запущенным, пока ПК меняет `.lab`-модуль и входной blob. Это позволяет измерять функцию на настоящем Cortex-A57 без каждого запуска всей игры. SDK Jit предоставляет отображения RW/RX; для запуска нужен application mode с доступными JIT-системными вызовами. Неподдерживаемая конфигурация возвращает `jit_unavailable`.

## Один тест

Сначала проверьте `python host/lab.py smoke`. Он загружает включённый integer-модуль и сравнивает результаты с независимой целочисленной формулой. Это проверка стенда, не оптимизация игры.

Контракт в `lab/include/lab_abi.h`:

```c
int32_t lab_module_entry(const LabHostAPI *api,
                         const LabRequest *request,
                         LabReply *reply);
```

Модуль читает входы только из `request->input`, использует предоставленный scratch и пишет результат в output с проверкой границ. Укажите `reply->size`, `abi_version`, `status`, `completed_iterations`, `checksum`, `output_bytes`. Регулярно проверяйте `api->should_cancel(api->context)`; лимит времени основан на **кооперативной** отмене.

Образ: 64-байтовый заголовок LAB1 и import-free ARM64 PIC text/rodata. Заголовок содержит ABI, длину, entry offset, flags и SHA-256 тела. Сборщик запрещает импорты, writable globals/BSS, TLS, абсолютные/неподдерживаемые релокации и прямые переходы за пределы образа. Не применяйте `-ffast-math` или FMA без отдельной проверки семантики исходной функции.

```powershell
python build.py --module path/to/baseline.c --name baseline
python build.py --module path/to/candidate.c --name candidate
python host/lab.py --out data/compare.json compare --baseline build/baseline.lab --candidate build/candidate.lab --input path/to/capture.bin --iterations 1000 --trials 7 --pairs 3
```

Клиент чередует A/B и B/A, проверяет output SHA/checksum, completed iterations и сохранение FPCR/FPSR. На mismatch сравнение завершается ошибкой. Никакой NRO-перезапуск между модулями не нужен. `cancel` запрашивает отмену, кнопка `+` отменяет активный тест или выходит из idle.

## Как подготовить функцию игры

1. Из профиля **игры** выберите конкретную дорогую функцию. Низкий FPS сам по себе не доказывает, что виновата математика.
2. Захватите реальные входы, ожидаемые выходы и нужное состояние до/после вызова. Не публикуйте приватные игровые данные вместе с комплектом.
3. Уберите зависимость теста от адресов процесса: замените указатели на offsets в blob с проверками длины. Воспроизведите важные aliasing и порядок доступа.
4. Сначала запустите исходный вариант и подтвердите полное совпадение результата. Граничные значения, NaN/denormal/overflow, режим округления и побочные эффекты должны соответствовать реальному контракту.
5. Затем сравнивайте нативную C/NEON-реализацию с теми же входами. Отсутствующие MMIO/callback/TLS нельзя заменять пустыми заглушками ради скорости.
6. Переносите выигрыш обратно в игру только с корректным условием допуска и исходным fallback. Измерьте весь кадр повторно.

Микротест не воспроизводит автоматически кэш, конкуренцию потоков или работу GPU полной игры. QEMU полезен для корректности ARM64-кода, но не подтверждает время на Cortex-A57.

## Что означает результат

В JSON сохраняются hashes образа/входов/выходов, warmup и измеряемые повторы, inner/outer ticks, реальное CPU-время потока или явная ошибка, core IDs, наблюдаемые частоты CPU/GPU/RAM и FPCR/FPSR до/после. Формат перечислен в `lab/source/main.c::report`.

Время в миллисекундах: `inner_ticks * 1000 / counter_hz`. Это системные тики, **не такты CPU**. Для нагрузки одного ядра используйте доступный thread CPU time, а не проценты из частоты таймера. Перед вызовом восстанавливаются входы и очищаются 4 MiB scratch/output вне замеряемого участка; это воспроизводимый reset-buffer режим, не точная модель игровых кэшей. Сохраняйте сырые повторы и частоты; не вычитайте произвольную «стоимость пустого вызова» и не переводите ускорение одной функции напрямую в FPS.

Нативный модуль имеет права приложения. Проверки формата не изолируют произвольные load/store/косвенные переходы и не спасают от бесконечного цикла без проверки отмены. При падении или некорректном модуле может потребоваться ручной запуск приложения. Автосон отключается только на время работы стенда, постоянные настройки системы не меняются.
